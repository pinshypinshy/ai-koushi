# AI講師

参考書をアップロードすると、AIがその内容を学習に適したステップへ分解し、
チャット形式の講義として順に解説する Web アプリ。理解度は選択式の確認テストで測定し、
誤答した問題だけを後から復習できる。

「読む」だけで終わりがちな参考書を、「解説される → 質問できる → 測定される」という
能動的な学習サイクルに変換することを目的とする。

## 現在の状態

**本番環境で稼働している。** https://ai-koushi.yuki-hiraishi.com

ログインし、教材を貼り付けて講義を作成し、生成の進捗を見て、解説を受けて質問し、
ステップを進め、確認テストを受けて誤答だけを復習する、までが本番環境で実データにより
動作する。Google サインインとゲストサインインの両方を本番で確認済み。
モックデータは残っていない。

受講の実測（2026-09-01、同じ講義）：③講義本文の生成が6.1秒で出力772トークン、$0.0039。
入力11,724トークンのうち11,555トークンがコンテキストキャッシュから読まれている。
⑤ステップ要約は2.0秒・$0.0009。1発話あたりの費用は1円に満たない。

**初回トークンの到達は4.1秒で、§8.1 の目標（3秒以内）を超えている。** 文字は約1.9秒かけて
少しずつ届いており、ストリーミング自体は経路上も動作している（Vite の proxy 経由でも
チャンクの間隔が保たれることを確認済み）。受講時の体感としては許容範囲だが、目標は未達である。

## 主な機能

- **サインイン** — Google アカウント（許可リスト方式）に加えて、運営が発行したID・パスワードによるゲストサインインに対応する。ログイン前でも「画面を見る」からサンプルを操作できる
- **講義作成** — サイドバーの「⊕ 新規講義」から開くオーバーレイで、教材のテキストを貼り付け、プレビューを確認して講義を作成する
- **教材タブ** — 作成に使った教材の原文を読み取り専用で表示する。AIの解説と原典を突き合わせるためのもの
- **講義タブ** — チャット形式で講義が進行し、途中で質問できる。右上に進捗状況を常時表示
- **確認テストタブ** — 4択の設問に回答する。正誤を記録し、誤答した問題のみを再挑戦できる
- **使い方ガイド** — サイドバー・講義作成オーバーレイ・空状態から開く。質問の候補を選ぶと、
  あらかじめ用意した回答を返す。AI を呼ばないため費用も上限も消費しない（§4.8）
- **運営管理ページ** — `/admin`。利用者ごとの上限に対する消費、AI呼び出しの明細、ログインの記録、
  許可リストとゲストの一覧、モデルIDと上限値とシステムプロンプトを読み取り専用で確認する（§4.7）

タブは「教材 / 講義 / 確認テスト」の3つで、いずれも選択中の講義に対するビューである。
講義の新規作成はタブに含めず、一時的なオーバーレイとして扱う。

設問はステップと1対1に対応せず、複数ステップを組み合わせないと解けない横断設問を含む。
各ステップを個別に暗記しただけでは解けない設問を混ぜることで、測定力を高めている。

## 技術構成

| レイヤ | 採用 |
|---|---|
| 実行基盤 | Cloudflare Workers |
| サーバー | Hono（JSON API・ストリーミング） |
| フロントエンド | React SPA（CSR）＋ Vite ＋ TypeScript ＋ Tailwind CSS |
| 長時間ジョブ | Cloudflare Workflows |
| DB | Cloudflare D1（SQLite） |
| AI | Gemini API（3.1 Pro preview / 3.7 Flash）＋ APIキー |

Cloudflare を選んだ理由は、**HTTP リクエストの実行時間に上限がなく、AI の応答待ちが
制約にならない**ため。制限されるのは CPU 時間で、`fetch()` の待機時間はそこに算入されない。
詳細は [REQUIREMENTS.md](REQUIREMENTS.md) §7.2 を参照。

Gemini を選んだ理由は、**受講中のコストが「教材全文を毎ターン読む」部分に支配されており、
キャッシュの読み取り単価がそのまま総額を決める**ため。講義1件あたり約 $0.56 で、
Claude 構成に対しておよそ1/5に収まる。他社との比較は §11.3.1 を参照。

ただし**講義作成（①②）だけは入力ではなく出力に支配される**。実測では作成コストの約9割が
出力トークンで、その65%が思考トークンだった。詳細は §8.2.2 を参照。

Pro 系で実在するモデルは `gemini-3.1-pro-preview` のみである（2026-08-27 時点）。
preview は予告なく変わりうるため、モデルIDは設定値として `server/wrangler.jsonc` に外出ししている。

## 開発

Node.js は `.node-version` で固定している（22.20.0）。

### 初回のみ

依存をそれぞれインストールする。

```bash
cd app && npm install
```

```bash
cd server && npm install
```

ローカルの D1 にマイグレーションを適用する。

```bash
cd server && npm run db:migrate
```

サーバーのシークレットは `server/.dev.vars` に置く（git 管理外）。雛形が用意してあるので、
`GOOGLE_CLIENT_ID`・`GOOGLE_CLIENT_SECRET`・`SESSION_SECRET`・`GEMINI_API_KEY` を埋める。
`SESSION_SECRET` は `openssl rand -base64 32` の出力でよい。

Google OAuth のクライアントには、承認済みリダイレクト URI として
`http://localhost:5173/auth/callback` と `http://localhost:8787/auth/callback` を登録しておく。

### 起動

2プロセスを並行して動かす。

```bash
cd server && npm run dev
```

```bash
cd app && npm run dev
```

ブラウザからは `http://localhost:5173` だけを使う。`/api` と `/auth` は Vite の proxy が
`http://localhost:8787` のサーバーへ転送するため、フロントとサーバーが同一オリジンに揃う。

| コマンド | 場所 | 内容 |
|---|---|---|
| `npm run dev` | app / server | 開発サーバー |
| `npm run build` | app | 型チェックと本番ビルド |
| `npm run lint` | app | ESLint |
| `npm run typecheck` | server | 型チェック |
| `npm run db:migrate` | server | ローカル D1 へマイグレーション適用 |
| `npm run guest:add -- <ID> "<表示名>"` | server | ゲストアカウントの発行。本番へは `--remote` を付ける |
| `npm run guest:reset -- <ID>` | server | ゲストのパスワード再発行。学習データは残る |
| `npm run limit:set -- <アドレス or ゲストID>` | server | 月間上限の個別設定。`--courses` と `--cost` の少なくとも一方を付ける |
| `npm run limit:clear -- <アドレス or ゲストID>` | server | 個別設定を取り消し、種別の既定値へ戻す |

リモートの D1 作成（`npm run db:create`）とデプロイには Cloudflare アカウントと
`wrangler login` が必要になる。ローカル開発だけなら不要。

### ゲストアカウントの発行

Google アカウントを持たない相手に使ってもらう場合は、ID とパスワードを発行する。

```bash
cd server && npm run guest:add -- yamada "山田さん"
```

パスワードは16文字を自動生成し、**実行時にのみ表示する**。保存されるのはハッシュだけで、
平文を後から取り出す手段は無い。ゲストの上限は月2件・$3 に絞ってある（§8.2.3）。

特定の相手にだけ枠を広げたい場合は、既定値を動かさず個別に上書きする（Q-31）。

```bash
cd server && npm run limit:set -- yamada --courses 5 --cost 8
```

指定しなかった側は既定値のまま追従する。取り消しは `npm run limit:clear -- yamada`。
個別設定が効いている利用者は、運営管理ページの一覧に「個別上限」として表示される。

パスワードを忘れた場合、ロックされた場合は再発行する。**学習データは残る。**

```bash
cd server && npm run guest:reset -- yamada
```

アカウントごと消す場合は利用者の行を削除する。**その講義・対話・確認テストの解答記録も
連鎖して消える**ため、パスワードを忘れただけの場合にこちらを使わないこと。

```bash
cd server && npx wrangler d1 execute ai-koushi --local --command "DELETE FROM users WHERE email = 'yamada@guest.local'"
```

### 運営管理ページ

`/admin` を開くと、利用者・費用・ログイン記録・認証の状態を一覧できる（§4.7）。**読み取り専用**で、
許可リストの追加やゲストの発行はコマンドのまま。開くには管理者の権限が要る。

```bash
cd server && npm run admin:add -- you@example.com
```

対象は**一度サインインした利用者に限る**。権限は `users.is_admin` に持たせており、行が無ければ
立てる先が無いため（許可リストに載せただけの相手にはまだ行が存在しない）。判定はリクエストの
たびに DB を引くので、取り消しは即座に効く。

```bash
cd server && npm run admin:list
```

```bash
cd server && npm run admin:remove -- you@example.com
```

最後の1人を外すと管理ページに誰も入れなくなるため、既定では拒否する（承知の上なら `--force`）。
本番に対して操作する場合はいずれも `--remote` を付ける。

### 依存を入れ替えたとき

`npm install` でパッケージを入れ替えたら、**開発サーバーを起動し直す**。ソースコードの変更は
自動で読み直されるが、`node_modules` と `wrangler.jsonc` は起動時に読み込まれたきりになる。
KaTeX を入れ替えた際、古い CSS が配信され続けて原因の特定に手間取った実例がある。

### 画面の確認

通常の操作では到達しにくい画面は、次のようにして確認する。開発用のモックデータと
画面切替パネルは、実データが揃った時点で削除した。

| 画面 | 出し方 |
|---|---|
| 全体の雰囲気 | ログイン画面の「画面を見る」。サンプル講義1件で3タブすべてを操作できる |
| 生成中（SC-05） | 実際に講義を作成する。3分ほど表示される |
| 生成失敗（SC-06） | 生成を失敗させる必要がある。意図的な再現手段は用意していない |
| 講義0件（SC-02） | 講義をすべて削除する |
| 復習モードの対象なし（SC-12） | 全問正解した状態で「誤答のみに取り組む」を押す |
| 運営管理ページ（§4.7） | `npm run admin:add` で権限を付けて `/admin` を開く。権限が無い場合の表示も同じ経路で確認できる |

モバイル版はブラウザの幅を 767px 以下にすると確認できる。
