# 要件定義書：将来拡張（§11）

## 11. Appendix：将来拡張

MVPの対象外とするが、設計上の余地を残しておく項目。

### 11.1 入力の拡張

| 項目 | 内容 | 設計上の含み |
|---|---|---|
| PDF取り込み | PDFをアップロードしてテキスト抽出 | `materials` に `source_type` を追加すれば対応可能。当面は §4.8.2 の変換プロンプトを利用者に配ることで代替する |
| 画像・図表 | 教材中の図をAIに解釈させる | マルチモーダル入力への拡張 |
| URL取り込み | Web上の記事を教材化 | 権利関係の検討が必要 |
| 教材の追記・差し替え | 既存講義への教材追加 | 骨子の再生成と既存進捗の突合が必要（§4.1.7） |

### 11.2 学習機能の拡張

| 項目 | 内容 |
|---|---|
| 出題形式の追加 | 記述式、穴埋め、並べ替え。記述式はAIによる採点が必要 |
| 選択肢数の再検討 | 4択で難易度が不足する場合、5〜6択への拡張。§5.3のディストラクタ品質要件が前提 |
| 間隔反復 | 忘却曲線に基づく復習タイミングの提示。`attempts` の履歴が既に十分な情報を持つ |
| 学習統計 | ステップ別正答率、学習時間、弱点分野の可視化 |
| 講義内容の手動編集 | AIが生成した骨子・設問をユーザーが修正 |
| 教材タブの参照機能 | 教材内の全文検索、見出しの目次表示、ステップと教材箇所の相互リンク。いずれも骨子生成が教材内の位置情報を返すことが前提（§4.4） |
| 確認テストの再生成 | 設問品質に問題がある場合にステップ単位で再生成する（Q-7でMVP対象外と決定）。解答記録との紐付けをどう扱うかの設計が前提 |

### 11.3 公開運用への移行および課金方式の代替案

| 項目 | 内容 |
|---|---|
| 課金 | 利用量ベースまたはサブスクリプション |
| レート制限 | ユーザー単位・IP単位の呼び出し制限 |
| BYOK | ユーザー自身のAPIキー利用オプション。コスト転嫁の手段となる |
| AIプロバイダの変更 | 出力品質やコストの前提が変わった場合の乗り換え。判断材料は §11.3.1 |
| 利用規約・プライバシーポリシー | 教材の権利関係、データの取り扱い、AI利用の明示 |
| 管理画面 | ユーザー管理、コスト監視、生成品質のレビュー |
| 講義の共有 | 生成済み講義を他ユーザーへ公開 |

#### 11.3.1 AIプロバイダの比較と、変更する場合の判断材料

MVP では Gemini を採用した（§1.4）。他社への変更を検討する場合の材料を残す。

**単価（2026年8月時点、1Mトークンあたり）**

| モデル | 入力 | 出力 | キャッシュ読取 | キャッシュ書込 |
|---|---|---|---|---|
| Gemini 3.7 Flash | $0.75 | $3.75 | $0.075 | 保存に時間課金 |
| Gemini 3.1 Pro | $2.00 | $12.00 | $0.20 | $0.375 |
| GPT-5.4 | $2.50 | $15.00 | $0.25 | — |
| Claude Sonnet 5 | $3.00 | $15.00 | $0.30 | $3.75〜$6.00 |
| GPT-5.6-sol | $5.00 | $30.00 | $0.50 | $6.25 |
| Claude Opus 5 | $5.00 | $25.00 | $0.50 | $6.25〜$10.00 |

**講義1件あたりの概算**

| 構成 | 概算 | 月8件 |
|---|---|---|
| Gemini 3.1 Pro ＋ 3.7 Flash（採用） | 約 $0.9 | 約 $7 |
| Claude Opus 5 ＋ Gemini 3.7 Flash | 約 $1.7 | 約 $14 |
| Claude Opus 5 ＋ Sonnet 5 | 約 $4.5 | 約 $36 |
| GPT-5.6 ＋ GPT-5.4 | 約 $4.1 | 約 $33 |

**Gemini を採用した理由**

| # | 理由 |
|---|---|
| 1 | 本アプリのコストは「教材10万トークンを毎ターン読む」部分が支配的で、キャッシュ読取単価で決まる。Gemini 3.7 Flash の $0.075 は Claude Sonnet 5 の1/4 |
| 2 | キャッシュ書き込みが $0.375 と、Claude の $3.75〜$6.00 に対して1/10以下。セッション再開のたびに書き込みが発生する本アプリの使い方と相性がよい |
| 3 | 単一プロバイダに揃えることで、SDK・認証・エラー処理・構造化出力の書式・キャッシュの課金方式がいずれも1系統で済む |

**採用しなかった構成**

| 構成 | 理由 |
|---|---|
| OpenAI | Claude とほぼ同水準の価格で、乗り換える金銭的な理由がない |
| Cloudflare Workers AI | 同一プラットフォーム内で完結する利点はあるが、提供モデルの単価が安くなく、10万トークン級のコンテキストキャッシュ運用に耐える構成が見当たらない |
| 上位モデルと下位モデルのプロバイダ混在 | 節約効果に対して統合面が2倍になる（SDK・認証・エラー処理・構造化出力・キャッシュ課金がすべて2系統）。個人利用の規模では割に合わない |

**変更を検討する条件**

品質面の懸念は、実測なしに判断すべきではない。**実際の参考書1冊で骨子と確認テストを生成し、ディストラクタの質を目視で比較する**こと。特に評価すべきは次の2点である。

| 観点 | 見るべきこと |
|---|---|
| 骨子生成（①） | 10万トークンの教材全体を読んだうえで、依存関係の通ったステップ順を組めているか。前提知識が後回しになっていないか |
| テスト生成（②） | ディストラクタが §5.3 R-3 を満たしているか。明らかな埋め草が混ざり、実質2〜3択になっていないか |

②に不満がある場合、まず ①② のみを上位モデルへ差し替える。§5.5 でモデルIDを設定値として外出しし、§5.8 で AI層を抽象化してあるため、この変更は局所的に収まる。月8件で $7 が $14 になる程度の差であり、**最初から高い構成を選んでおく必要はない。**
